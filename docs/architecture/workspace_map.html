First time here? Try Tour → First-time onboarding for a 10-minute guided walk-through (eight steps, narration + reconfigured graph at each step).

Layout. The default is Dependency tiers. An edge A → B means A depends on B. A crate's tier is the longest depends-on path dagre's longest-path ranker assigns after its depth-first (DFS) cycle break. Nodes are inserted in id order and edges in source, target, id order, and dagre 0.8.5 does not use a random seed, so the same graph always gets the same positions. Tier 0 (no workspace dependency, including astraweave-math) is the top row. Each deeper tier is the next row down: astraweave-ecs sits under the crates it depends on, astraweave-core under ecs and behavior, and aw_editor plus the examples bundle on the bottom rows. Consumers are drawn beneath the crates they use, so the foundation feeds downward. An edge points upward when its target sits on a higher row than its source. The upward and downward counts are filled from that layout. A downward edge is not a dependency cycle. When the downward edges are the runtime edges declared in veil.md, review #733 E3 reports those as reversed; PR #737 removes that reversal, and the count above follows the layout rather than a fixed number. Domain clusters (fcose) stays in the Layout menu and is the force layout; Re-explode reshuffles only that one. If fcose is not registered, that choice uses the built-in cose layout. Dependency hierarchy (dagre) and Dormancy stratification stay selectable too. A direct file:// open skips the integrity check on the six libraries. GitHub Pages and any http or https server keep integrity and crossorigin on those files.

Click any node for crate detail. The click also highlights that crate, its dependencies (green border) and its dependents (orange border), and dims everything else. Hops is 1, 2, or all: follow depends-on edges that many steps, and used-by edges that many steps. Click the background or press Esc to clear the highlight. Tooltips, trace links, search, and the side panel keep working. The side panel uses progressive disclosure: surface info visible, deeper sections (deps, integration types, open questions, silent failures) behind ▸ expanders. Blast radius (toggle, default on): selecting a node also highlights its dependents within 3 hops — orange = direct, faded = transitive. Honest dependency-graph highlighting, not behavioral simulation. Those dependents stay visible even when they sit outside the hop setting. Focus mode (toggle, off by default): hides everything outside the selected node's 1-hop neighborhood. The Hops menu does not change that toggle. Stories dropdown for narrative views (Dual-World Bridge, Editor↔Engine Boundary, Silent-Failure Map, Dormant Surface, AI Pipeline, Networking Coexistence, Aspirational Docs). Path-find: Pick A → node → Pick B → node → Show path highlights the shortest directed dep chain. Share ↗ copies a URL that reproduces the exact current view (filters, selection, tour step, layout). Domain chips (v2.1): click any chip to add that domain to the include set. Nothing checked = no filter (show all). Any subset checked = show only those domains. All checked = same as none. Chips lock during a story or tour — use Reset to clear. Visual encoding: node size = LoC band; fill colour = domain (Wong colourblind-safe palette); dashed border = dormant; ⚠ = silent-failure locus; 📄 = traced. Edges (v2.1) are linear gradients from source-domain colour to target-domain colour — same-domain edges look uniform, cross-domain edges show the transition. Anomalous edges remain solid red; declared-but-unused edges remain dashed grey. Keyboard: Esc clears the click highlight and path-pick (it does not clear a search box while that box is focused); ← → navigate tour steps. On mobile, tap ☰ Controls for the toolbar; the side panel becomes a bottom sheet.
